## 2026-07-10 无硬件测试基线与安全边界

背景：

- 当前没有可用机器人，控制链路重构缺少真实硬件回归条件。
- 原 `test/` 同时包含单元测试和导入即访问硬件的诊断脚本，不能安全执行完整 `pytest`。

改动：

- 新增独立 `tests/` 离线测试入口和 fake arm / gripper backend。
- 覆盖状态机、动作仲裁、同步采样、相机资源冲突、Quest3 数学和 HDF5 写盘。
- 推理动作增加有限值校验和超时归零保护，默认超时为 250 ms。
- HDF5 writer 改为消费完关闭命令之前的队列内容后退出，并向上反馈关闭失败。
- 核心动作模型不再要求导入 ROS 消息包，便于普通 Python 环境执行测试。
- 新增 GitHub Actions 离线测试工作流。
- 将遥操作设置和按键捕获对话框迁移到 `gui/dialogs/`，并为 GUI 包启用懒加载。
- 使用 PySide6 offscreen 和 pytest-qt 覆盖对话框构建、配置保存和按键输入。
- 三种遥操作设置页使用独立滚动区，避免内容将对话框撑出小屏幕。

验证：

- `python -m pytest`：37 项通过。
- 97 个项目和测试 Python 文件通过 AST 语法解析。

后续：

- 有机器人后验证推理超时阈值、控制器切换、Home 轨迹和真实停止距离。
- GUI 拆分应继续采用小步重构，并保持离线测试持续通过。

## 2026-07-11 相机控制器与 GUI 面板拆分

背景：

- `main_window.py` 同时承担 SDK 相机发现、下拉框填充、MediaPipe profile 映射、相机占用状态和偏好保存，界面逻辑难以独立测试。
- 当前没有相机和 ROS 环境，需要在不启动完整主窗口的条件下验证拆分结果。

改动：

- 新增 `gui/controllers/camera_selection.py`，集中管理相机发现、去重排序、选项标签、序列号、MediaPipe 话题、运行状态和偏好快照。
- 主窗口改为通过 `CameraSelectionWidgets` 提供控件引用，并把相机选择逻辑委托给控制器。
- 移除主窗口中的相机选项缓存和重复实现，控制器成为相机选择状态的唯一持有者。
- 删除主窗口中从旧 Dock/Tab 方案遗留的 19 个无入口界面方法及专用导入。
- 新增纯 Qt 的 `SystemControlPanel`、`StatusOverviewPanel`、`DataRecordingPanel` 和 `InferencePanel`；主窗口保留属性桥接、命令信号和全部运行编排。
- `main_window.py` 由 3933 行、192 个方法缩减为 2537 行、172 个方法，活动 `setup_ui()` 由 571 行缩减为 187 行。
- 首次填充推理相机下拉框时使用已保存序列号；后续刷新继续保留用户当前选择。
- 新增 6 项 offscreen Qt 测试，覆盖多相机排序、重复设备、无设备刷新、过期序列号、话题映射、配置快照和占用状态。
- 新增 8 项面板测试，覆盖配置默认值、录制路径、推理后端、隐藏/禁用状态、命令按钮属性、提示控件布局和状态标签映射。

验证：

- `python -B -m pytest -q -p no:cacheprovider`：51 项通过。
- 107 个项目和测试 Python 文件通过 AST 语法解析。
- `git diff --check` 通过，仅有仓库既有的 CRLF 转换提示。

后续：

- 当前 `setup_ui()` 已只保留面板装配、属性桥接和信号连接；除非进行视觉重设计，不再继续机械拆分。
- 有真实相机后补充 SDK 热插拔、同型号多设备和 ROS 图像话题联调。

## 2026-07-11 GUI 视觉现代化

背景：

- 原界面双列排版紧凑、工作流清晰，但依赖系统默认控件和零散局部颜色，视觉层级偏旧。
- GUI 本身是可替换表现层，控制、录制、推理和 ROS 行为继续由下一层承担；当前无真实机器人，不应借视觉改造修改设备行为。

改动：

- 新增纯 Qt 的 `gui/theme.py`，统一 Fusion palette、字体、控件尺寸、边框、状态标签、按钮语义和滚动条样式。
- 新增 `WorkspaceShell`，提供紧凑顶部状态栏以及 48:52、两侧独立滚动的双列工作区。
- 保留第一版 GUI 的紧凑信息顺序；系统配置恢复同一行组合，`1280x800` 首屏可直接看到监视器按钮和完整日志，不需要横向或纵向滚动。
- 状态总览改为左右并列的无嵌套 section，避免 GroupBox 套 GroupBox。
- 用 `primary`、`secondary`、`warning`、`danger` 等 role 取代面板局部 QSS，并给刷新、选择、启动、停止、预览和删除命令补充 Qt 标准图标。
- 将容易误解为硬件急停的按钮文案改为“停止推理输出”；内部属性、回调和停止行为保持不变。
- 新增 `scripts/render_gui_preview.py`，用 idle、running、error 三组假状态在无 ROS、无相机、无机器人环境离屏渲染真实 shell、theme 和 panel。
- 更新 README GUI 截图和架构边界说明，生成物默认写入已忽略的 `artifacts/gui/`。

验证：

- `python -B -m pytest -q -p no:cacheprovider`：60 项通过。
- 112 个 `src/teleop_control_py`、`tests` 和 `scripts` Python 文件通过 AST 语法解析。
- `1440x900`、`1280x800` 的 idle 截图以及 `1280x800` 的 running/error 截图完成像素级人工检查；无重叠、无文字越界，1280 尺寸两列无滚动溢出。
- GUI panels 与 theme 在新进程中导入后未加载 `rclpy` 或 `ament_index_python`。
- `git diff --check` 通过，仅有仓库既有的 CRLF 转换提示。

后续：

- 有 Linux ROS 桌面和真实设备后确认系统字体差异、窗口缩放以及动态按钮状态，但不需要为本次视觉改造进行机器人动作测试。

## 2026-07-11 GUI 辅助窗口现代化

背景：

- 主工作区完成现代化后，相机监视器、HDF5 回放器和遥操作设置仍存在大图撑宽、窄窗溢出、局部样式不统一和异常状态不清晰的问题。
- 当前没有机器人、相机或 ROS 图，辅助窗口只能使用 Qt offscreen、假图像和临时 HDF5 数据验证。

改动：

- 新增共享 `ImageViewport`，保存原始 pixmap 并按稳定 size hint 等比例绘制；4K 假帧不再改变窗口最小尺寸。
- 相机监视器改为双画面加机器人状态侧栏；长路径和状态按宽度省略并保留完整 tooltip，坏帧会清除旧画面，录制失败状态不会被后续空闲状态覆盖。
- HDF5 回放器将命令区整理为四行，路径区自适应吸收剩余宽度；空文件、缺失文件、加载失败、空 demo 和读帧失败均有明确状态并禁用无效命令。
- 三种遥操作设置页统一页签、滑杆、下拉框、步进框和命令样式；最小窗口 `480x360`，在 `500x400` 下无横向溢出，底部“关闭/应用”始终可见。
- 参数方案命令改为“另存方案”，准确表达每次都会询问新名称的行为。
- 主界面的实时预览入口移到顶栏，左侧分组简化为“日志”并只保留只读日志框；原按钮对象、信号连接和打开窗口回调保持不变。
- 推理动作输出框由 `50px` 增至 `75px`；日志正文固定为 `130px`，在 `1280x800` 和 `1440x900` 下与模型推理面板保持同一底边。
- “停止推理输出”保留原回调和停止行为，但由急停式实心红调整为警告级样式，避免误解为硬件 E-stop。
- 相机、HDF5 和设置窗口继续使用原公开属性、信号和服务边界，没有修改 ROS、设备或控制链路。

验证：

- `python -B -m pytest -q -p no:cacheprovider`：81 项通过。
- 116 个 `src/teleop_control_py`、`tests` 和 `scripts` Python 文件通过 AST 语法解析。
- 主界面 idle/running/error 在 `1440x900` 和 `1280x800` 下完成离屏检查；辅助窗口在 `1100x700`、`1080x720`、`900x600` 和 `500x400` 下无重叠或横向溢出。
- GUI theme、panels、widgets 和 dialogs 在新进程中导入后未加载 `rclpy` 或 `ament_index_python`。
- `git diff --check` 通过，仅有仓库既有的 CRLF 转换提示。

后续：

- 有真实设备后只需补充动态帧率、相机热插拔、录屏编码失败和高 DPI 字体差异验证；本轮纯界面改造不要求机器人动作测试。
